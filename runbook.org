The same setup as [[file:overview.org][the home laptop as the hub]], written so that you do every step yourself and know
why you are doing it. Each step says *where* to run it, *what* to type, *why*, *how to check it
worked* and, for the risky ones, *how to undo it*. In Emacs, =C-c C-t= on a step marks it DONE, and
each phase heading counts its steps.

*Start here: phase A, step A1.* What each helper does, in plain words:
[[file:helpers.org][helpers.org]]. When something breaks later: [[file:recovery.org][backups and recovery]].

The helper scripts in =bin/= (next to this file) do exactly these steps. Where a helper covers a step, the
step says so. You can use the helper for the boring part once you have done a step by hand and
understood it.

Where to run each step: =HOME= = home laptop (Arch, user =archx=) · =WORK= = work laptop (Ubuntu,
user =hlima=) · =PHONE= · =CLUSTER= · =BOTH= = both laptops.

T=$(mktemp -d); : > $T/rc
TASKRC=$T/rc task rc.data.location=$T rc.hooks=0 rc.confirmation=0 import $S/task-export.json

** DONE B2 · =HOME= Understand how the drive is mounted today
#+begin_src sh
findmnt /run/media/archx/Toshiba_4T
#+end_src
Check the internal data disk the same way: =findmnt /mnt/StorageHDD= and =grep StorageHDD /etc/fstab=.
It should already be in =/etc/fstab=, because it is mounted under =/mnt=. If there is no line for it,
add one for it too in B4, with =nofail=.
*Why.* =/run/media/archx/…= is where the desktop (udisks) mounts a drive *when you log in*. When
nobody is logged in, for example after a reboot, the drive is not mounted and a backup would
fail. An entry in =/etc/fstab= mounts it at boot instead.

** DONE B3 · =HOME= Identify the partition
#+begin_src sh
lsblk -f
#+end_src
Find the line whose MOUNTPOINTS is =/run/media/archx/Toshiba_4T=, or whose LABEL is =Toshiba_4T=.
Copy its NAME (for example =sdb1=), FSTYPE and UUID into the values sheet. Use the UUID, never
=/dev/sdb1=: the sd letters can change between boots and between USB ports.

** DONE B4 · =HOME= Edit /etc/fstab safely
1. Make a backup:
   #+begin_src sh
   sudo cp /etc/fstab /etc/fstab.bak-2026-09-25
   #+end_src
2. Unmount the desktop's mount, so the new entry can take over:
   #+begin_src sh
   udisksctl unmount -b /dev/sdb1          # your NAME from B3
   #+end_src
3. =sudoedit /etc/fstab= and add *one* line at the end, the one that matches your FSTYPE:
   #+begin_example
   # Toshiba 4T backup drive — added 2026-09-25 (home hub)
   UUID=xxxx-xxxx  /run/media/archx/Toshiba_4T  ext4   defaults,nofail,x-systemd.device-timeout=10s               0 2
   UUID=XXXXXXXXXX /run/media/archx/Toshiba_4T  ntfs3  uid=1000,gid=1000,nofail,x-systemd.device-timeout=10s   0 0
   UUID=XXXX-XXXX  /run/media/archx/Toshiba_4T  exfat  uid=1000,gid=1000,nofail,x-systemd.device-timeout=10s   0 0
   #+end_example
   What the options mean:
   - =nofail=: if the drive is unplugged, the laptop still boots instead of dropping to an
     emergency shell. *This is the option that matters most.*
   - =x-systemd.device-timeout=10s=: boot waits at most 10 seconds for the drive.
   - =uid=1000,gid=1000=: NTFS and exFAT have no Linux owners, so this makes every file owned by
     you (check your numbers with =id -u= and =id -g=).
   - The last two numbers: =0 2= means "check the ext4 filesystem at boot, after the root disk".
     NTFS and exFAT get =0 0=.
4. Check the file before trusting it:
   #+begin_src sh
   sudo findmnt --verify --verbose      # must end with "0 parse errors, 0 errors"
   #+end_src
5. Mount it with the new rule:
   #+begin_src sh
   sudo systemctl daemon-reload
   sudo mkdir -p /run/media/archx/Toshiba_4T      # /run is emptied at boot; systemd recreates it then
   sudo mount /run/media/archx/Toshiba_4T
   findmnt /run/media/archx/Toshiba_4T             # SOURCE is your partition, OPTIONS contain nofail
   #+end_src
*If an NTFS drive refuses to mount* ("volume is dirty"): it was last unplugged from Windows without
ejecting it. Run =sudo pacman -S ntfs-3g && sudo ntfsfix -d /dev/sdb1=, then mount again.
*Undo.* =sudo cp /etc/fstab.bak-2026-09-25 /etc/fstab && sudo systemctl daemon-reload=.

** DONE G5 · =HOME= Import the merged tasks into a fresh database
*CHECKPOINT*: a safety snapshot from today, copied to the drive. This step moves =~/.task= aside.
1. Bring the work export over. On the work laptop: =scp ~/tw-work.json home:=
2. Merge the two exports. Tasks are matched by UUID, and when a task exists in both with different
   content, the one with the newer =modified= time is kept:
   #+begin_src sh
   cd ~
   python3 ~/sys_org/home_hub/bin/tw-merge-exports.py tw-home.json tw-work.json > tw-merged.json
   #+end_src
   Read the report it prints. Copy the "different on both" lines into a note, so you can check
   those tasks after the import.
   /Without the helper:/ =task import= overwrites a task that has the same UUID, so the file you
   import *last* wins for every task in both. Import the laptop you used least recently first, then
   the other one. That is a coarser rule than the helper's.

* Phase N — Remote computing: Jupyter, Quarto, and ports [0/8]
The home laptop does the computing (CPU, RAM, Docker); the work laptop and the phone only show the
result. Two ways to reach a service running at home, and when to use each:
- *On the tailnet address* (N3): for notebooks and web interfaces you start and stop often. No
  tunnels; the phone can open them too. Only your own devices can reach that address.
- *Through SSH on =127.0.0.1=* (N4): for services that restart at boot, anything without a password,
  and one-off ports.

2. In =~/.bashrc=:
   #+begin_src sh
   fwd()   { ssh -O check home 2>/dev/null || ssh -fN home; for p in "$@"; do ssh -O forward -L "$p:localhost:$p" home && echo "localhost:$p -> home:$p"; done; }
   unfwd() { for p in "$@"; do ssh -O cancel -L "$p:localhost:$p" home; done; }
   #+end_src
3. Use:
   #+begin_src sh
   fwd 8880 4200          # open http://localhost:8880 and http://localhost:4200 on the work laptop
   unfwd 4200             # close one
   ssh -O exit home       # close the shared connection and all its tunnels
   #+end_src
*This replaces* the old =ssh -p 22 -N -L 8880:localhost:8880 user@server=: the address, port 2255,
user and key come from the =Host home= entry, and Tailscale makes it work from home and from work
alike. /Optional/ — a fixed pair you open every day can live in its own entry:
#+begin_example
Host home-dev
  HostName home.tail53b947.ts.net
  User archx
  Port 2255
  IdentityFile ~/.ssh/id_ed25519_home
  IdentitiesOnly yes
  LocalForward 8880 localhost:8880
  LocalForward 4200 localhost:4200
  ExitOnForwardFailure yes
  ServerAliveInterval 30
#+end_example
Then =ssh -N home-dev=.
